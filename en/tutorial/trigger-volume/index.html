Trigger volumes: world events without code

The invisible box that teleports, plays sound, gives items and switches a whole dungeon on. Command by command.

by OrbisHytale · September 18, 2026

A trigger volume is an invisible box in the world. When somebody enters it, leaves it or stays inside, the server fires an effect: teleport, play a sound, change the weather, give an item, open a door, paste a prefab. It is how you build an arena, a lobby, a dungeon or an event without writing a line of code.

Everything here comes from the TriggerVolumes plugin that ships with the server. The command is /triggervolume, aliased /tv. It needs the world editor permission group.

The fast way: the tool

/tv tool

That puts EditorTool_TriggerVolume straight into your hand. With it you draw the volume by looking at the world, no coordinates to memorise.

To see the volumes that already exist:

/tv view

Toggles the debug drawing of the boxes. Without it you see nothing, because in game a volume is invisible.

Creating by hand

/tv create <name> <shape> <dim1> <dim2> <dim3>

The volume is born at your position. There are three shapes:

  • box — dim1 is the radius on X, dim2 the height, dim3 the radius on Z. So box 5 4 5 is a 10 × 4 × 10 box.
  • sphere — dim1 is the radius, dim2 raises the centre.
  • cylinder — dim1 is the radius, dim2 the height.

A whole room:

/tv create boss_room box 12 8 12

Attaching an effect

The effect is not typed out: it comes from a ready-made effect asset.

/tv effects

Opens the effect editor for the selected volume. To list and pick an existing asset:

/tv browse
/tv assigneffect <volume> <effectId>

Careful: assigneffect replaces everything on the volume — conditions, effects and rejection effects. It does not add, it swaps. To clear it, /tv unassigneffect.

What you can fire

The built-in effect list is long. The ones you will actually use:

  • Teleport and velocity — jump pads, portals, knockback
  • Sound, VFX, particles and music — area ambience
  • Message and event title — a warning on entry
  • Give item, damage, game mode
  • Respawn point and world spawn
  • Place block, replace block type, control doors
  • Paste prefab, spawn NPC, remove entities
  • Time and weather
  • Enable, disable and delete another volume — this is how you chain an event

And you can send a signal (SendSignal), which is what wires one volume to the next.

Who triggers it

A volume does not only react to players. It tells three targets apart: player, NPC and item drop. A volume that removes dropped items falling out of the map uses exactly that.

If an entity must never trigger anything, it gets the IgnoreTriggerVolumes component.

Working in bulk with tags

On a real map you do not touch one volume at a time. Every box can carry tags:

/tv tag add <volume> <key>
/tv enabletag <key>
/tv disabletag <key>
/tv listtag <key>

With that you switch a whole dungeon off with one command and back on when the event starts. To apply an effect to a group at once, /tv assigngroupeffect.

The rest of the day to day

/tv list              list everything
/tv info <name>       shape, tags and effects
/tv tp <name>         teleports you to it
/tv rename <a> <b>
/tv enable <name>     /tv disable <name>
/tv remove <name>

Testing without breaking anything

/tv test

Spawns a set of demo volumes in front of you, one per shape and effect type. Run it again and it cleans up. It is the best way to see how each effect behaves before touching the real map.

Two warnings

Volumes are cheap but not free: every entity in the world is tested against the boxes. Hundreds of active volumes at once cost real time — there is even a /tv benchmark in the server to measure it. Prefer enabling by tag only what is in use.

And remember: this is the pre-release. Subcommand names and the effect list can still change between builds.
